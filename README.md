# Receipt Analyzer

## Описание
Receipt Analyzer — это сервис для распознавания и валидации чеков по QR-коду. Пользователь загружает фото QR-кода (в формате JPG или PDF), сервис распознаёт QR-код, получает по нему данные о чеке, валидирует их через ФНС (или OpenAPI, интегрированный с ФНС), и сохраняет всю информацию в базу данных PostgreSQL.

### Какие данные получает сервис:
- Дата и время покупки
- Общая сумма
- Фискальный накопитель
- Номер чека
- Номер смены

Сервис также временно генерирует список покупок из разных категорий (в будущем — получение реальных данных о покупках из ФНС/OpenAPI).

## Как работает сервис
1. Пользователь загружает фото QR-кода чека через web-интерфейс или REST-запрос.
2. Сервис распознаёт QR-код, извлекает и валидирует данные чека.
3. Генерируется (или в будущем — запрашивается) список покупок.
4. Все данные, включая `clientId`, сохраняются в PostgreSQL.

## Валидация чека
- Проверка чека осуществляется через ФНС или OpenAPI (интеграция с ФНС).
- Проверяется подлинность чека и корректность суммы.

## Web-интерфейс
- Доступен по адресу: `http://localhost:8080/upload` (или другой порт, если изменён в настройках)
- Необходимые поля: ID клиента и файл с QR-кодом чека (JPG или PDF)

## REST API
- Основной эндпойнт: `POST /receipt/qr`
- Формат запроса: `multipart/form-data` с параметрами:
  - `file` — файл с изображением QR-кода (JPG или PDF)
  - `clientId` — идентификатор клиента (обязательный)
- Ответ: JSON с данными чека

## Swagger
- Документация и тестирование API доступны по адресу: `http://localhost:8080/swagger-ui.html` или `/swagger-ui/index.html`

## Требования
- Java 17+
- PostgreSQL
- Maven

## Запуск
1. Склонируйте репозиторий и перейдите в папку проекта.
2. Установите параметры подключения к БД в `src/main/resources/application.properties`.
3. Соберите и запустите приложение:
   ```bash
   mvn clean package
   java -jar target/receipt-analyzer-*.jar
   ```
4. Перейдите в браузере по адресу `http://localhost:8080/upload` для web-интерфейса или используйте Swagger для тестирования REST API.

## Примечания
- Список покупок генерируется случайно — это временное решение для демонстрации.
- В будущем планируется интеграция с ФНС для получения реальных данных о покупках.
- Все ошибки (например, неверный формат файла, превышение размера, отсутствие QR-кода) обрабатываются и возвращаются в удобном для пользователя виде.
